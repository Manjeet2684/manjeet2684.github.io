# Portfolio source

Static site: HTML, CSS and vanilla JavaScript. No build step, no framework, no
dependencies. Double-click `index.html` and it works.

## Run locally

```powershell
# optional, only needed if you want a real http:// origin
python -m http.server 8080
```

Then open <http://localhost:8080>.

## Files

| File | Role |
|---|---|
| `js/site-data.js` | **All homepage content.** This is the file you edit. |
| `index.html` | Homepage structure + a static copy of the content (the no-JavaScript fallback) |
| `saakh.html` | SAAKH case study |
| `upi-mesh.html` | Offline mesh payment simulation case study |
| `rbac.html` | Common Login / RBAC case study |
| `css/styles.css` | Theme: tokens, layout, components, print styles |
| `js/main.js` | Renders `site-data.js`, builds the case-study contents list, highlights the current section |
| `resume/Manjeet_Tiwari_Resume.pdf` | Copy of `../output/` — refreshed by `../resume/compile.ps1` |

## How the homepage works

`index.html` ships with real content already written into it, so the page is
readable with JavaScript disabled or if a script fails to load. When JavaScript
runs, `main.js` replaces the marked containers (`id="js-…"`) with whatever is in
`window.SITE`. So:

- **Normal editing:** change `js/site-data.js`.
- **Keep the fallback honest:** mirror important changes into `index.html`.

Section numbers (`01`, `02`, …) are generated by CSS counters. Add, remove or
hide a `<section data-sec>` and the numbering fixes itself — a hidden section
does not consume a number.

Case-study headings are numbered the same way. Write `<h2>Idempotency</h2>`,
never `<h2>6. Idempotency</h2>` — the number and the contents list entry are
both generated.

## Coding profiles

```js
links: {
  leetcode: "https://leetcode.com/u/your-handle",
  gfg: "https://www.geeksforgeeks.org/user/your-handle",
}
```

While both are `null`, the "Problem solving" section stays hidden and no empty
placeholder is shown. Do not publish solved counts or ratings you cannot prove.

## Adding a case study

1. Copy `rbac.html` to `your-project.html`.
2. Replace the `<h1>`, the `.glance` facts, and the `.article-body` sections.
3. Keep `<aside class="toc" id="toc"></aside>` — the contents list builds itself
   from the `<h2>` headings. Leave the headings unnumbered.
4. Add the project to `SITE.projects` in `js/site-data.js`, including a short
   `problem` line — the cards lead with it.

## Accessibility and behaviour that must stay

Skip link, `aria-current` on the active nav item, visible focus rings,
`prefers-reduced-motion` support, and a layout that works down to 360px.

## Publishing to GitHub Pages

Only when you decide to:

1. Run `..\resume\compile.ps1` so the bundled PDF is current.
2. Copy the contents of this folder to the Pages repository root.
3. Confirm `index.html` sits at the repository root.
