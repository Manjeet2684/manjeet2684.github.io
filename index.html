SAAKH Flagship

ProblemRetries, duplicate requests and concurrent debits turn a straightforward transfer API into double-spends and missing events.

A correctness-focused financial transfer and reconciliation backend. Spring Boot monolith where PostgreSQL is the source of truth and Kafka is only ever touched after commit.

  • Guarantee. One PostgreSQL transaction writes the debit, credit, transfer row, double-entry ledger lines, idempotency record and outbox event.
  • Concurrency. Accounts are locked with ordered SELECT … FOR UPDATE, so overlapping A→B and B→A transfers cannot deadlock or lose updates.
  • Retries. An Idempotency-Key plus a SHA-256 body fingerprint replays the original transfer and rejects conflicting reuse with 409.
  • Proof. 47 automated tests, Testcontainers for PostgreSQL and Kafka, run on GitHub Actions.

UPI Offline Mesh Payment System Simulation

ProblemA payment instruction cannot reach a server that has no network — and once it finally arrives, several devices may deliver the same one.

A simulation of deferred settlement without connectivity: encrypted payment packets hop a software mesh of untrusted devices until an internet-connected bridge uploads them.

  • Confidentiality. Hybrid RSA-OAEP key wrapping over AES-256-GCM payloads, so intermediate devices only ever see opaque ciphertext.
  • Integrity. GCM tag verification, signedAt freshness windows and SHA-256 ciphertext hashing before anything settles.
  • Duplicates. An atomic hash claim plus a unique packet-hash constraint means concurrent duplicate deliveries settle once.
  • Scope. A simulation and teaching demo — not NPCI, not a UPI switch, not a live payment network.

Common Login Module (RBAC) AuthN / AuthZ

ProblemAPIs leak when identity and permission are decided in the same controller check.

A reusable Spring Security login module that keeps authentication and authorization as two separate decisions instead of one tangled controller check.

  • Authentication. JwtAuthenticationFilter, CustomUserDetailsService and BCrypt populate the security context before controllers run.
  • Authorization. USER / MODERATOR / ADMIN roles enforced with method-level @PreAuthorize, including admin-or-self access.
  • Failure modes. Global JSON handling for 401, 403 and validation errors, and a filter chain that fails closed.
